# Спектральный обруч — Fourier Scratching

Рабочая реализация: `experiments/steel-shift-cube/index.html?puzzle=scratch`.
Это отдельная головоломка; прежний режим `fourier` сохраняет независимые фазу
и громкость шести рифов.

## Музыка и цель

Три комплексных коэффициента задают поле управления, а не FFT звукового файла.
Берём принцип редактирования спектров музыкальных параметров из
[Scratching the Scale Labyrinth](https://oro.open.ac.uk/28690/1/ScaleLabyrinth-Final.pdf).
Группа ходов, ограниченный декодер и игровой обруч — адаптация проекта.

Опорные коэффициенты: `c* = (0.48, 0.30, 0.18)`.

```
d(t)  = Σ[k=1..3] (c[k] − c*[k]) exp(2πikt)
h(t)  = t + 0.2 Im(d(t)) / (2π)
g(t)  = 1 + 0.4 Re(d(t))
```

Авторская атака в `t` перемещается в `h(t) mod 1`. Конец ноты проходит через
ту же функцию: gate становится `h(t + duration) − h(t)`. Относительная громкость
`g(t)` умножает авторский `postgain`, сохраняя тембр; явный `value.duration`
также масштабируется, поскольку нативный звук может использовать его вместо Hap.
Высоты, инструменты, velocity, число событий и идентичность нот сохраняются.
В цели поле равно нулю, воспроизводятся исходные Strudel Patterns.

Поле действует на одну авторскую игровую партию: сначала пробуется `riff`,
затем остальные партии по имени. Все фрагменты выбранной партии используют
одно поле. Это может быть несколько дорожек эквалайзера. Остальные игровые
партии и фон сохраняют исходные Patterns. Совместимость проверяется на полном
графе: нужны 384 различных результата, ни одной ложной цели и тихого ребра.
Несовместимость возвращает явную ошибку, параметры ради неё не ослабляются.

## Алгебра и плавность

Состояния — перестановки трёх коэффициентов и независимые повороты каждого
на четверть оборота: `(Z/4Z)^3 ⋊ S3`, всего 384. Поворот `c[k] *= i`
имеет порядок 4; соседний обмен — порядок 2. Перестановки и повороты в общем
не коммутируют. Подсказка использует полный BFS-граф, диаметр — 8 ходов.

Переход фазы идёт по дуге. Обмен `(a,b)` анимируется унитарно:
`p=(a+b)/2`, `q=(a-b)/2`, `(p+exp(iπu)q, p-exp(iπu)q)`.
Энергия коэффициентов `Σ|c[k]|² = 0.3528` сохраняется и между положениями.
Это не утверждение о постоянной мощности итогового аудиомикса.

Для всех таких переходов по неравенству Коши:

```
0.20448 < g(t) < 1.79552
h'(t) > 0.23151
```

Круговое время остаётся монотонным, ноты не обгоняют друг друга, громкость
положительна. Границы не доказывают сохранение гармонии с аккордами фона,
слышимость изменения или интерес головоломки; нужна музыкальная приёмка.

## Представление и ввод

Угол точки обруча — момент атаки, радиус — относительная громкость. Круг —
цель. Точки взяты из реальных атак активной партии, совпавшие атаки объединены
для рисунка. Три малых селектора показывают волны с одной, двумя и тремя
осцилляциями. Номер/наконечник выбирает волну; наконечник перетаскивается по фазе.
Радиус ручки постоянный для тачскрина; высота маленькой волны показывает модуль.
Редактировать модуль произвольно нельзя: он меняется только обменом коэффициентов.

Нижняя панель: −90°, +90°, обмен с соседней волной, общая подсказка. Внутри
модели нет операционных кнопок. После выбора повторный клик на левой/правой
половине большого обруча тоже меняет фазу. Наведение без жеста не выбирает волну
и не запускает прогноз. Перетаскивание непрерывно обновляет модельный рисунок
и эквалайзер; отпускание фиксирует ближайшую четверть одним undoable-ходом.
Звук меняется после фиксации на общей доле транспорта. Cancel, пауза и смена
поля отбрасывают жест. Старт — собранный, `shuffle()` возвращает один показанный ход.

## Расширение контракта

Версия схемы остаётся `music-puzzle/2`. Добавлены проекция `fourier-scratch/1`
и явное `controls:3` отдельно от `fragments:6`. Прежний `complex-riff/2`
сохраняет свою проверку соответствия «один контрол — один фрагмент».

В `music-projection.js` выбор стратегии и непрерывного preview теперь общий.
`PuzzleMusic` не вызывает FourierBinding напрямую. Результат сохраняет
`music-projection/1`; дескриптор дорожки может содержать `controlKeys`, когда
несколько органов управления меняют одну дорожку. Представление получает
подготовленную привязку `binding`, чтобы не повторять выбор партии из звукового кода.
Композиции, транспорт, ActionFocus, ввод и раскладка кнопок не получают правил обруча.

## Проверки

`test-scratch.cjs` — полный граф, обратимость/периоды, BFS-подсказки,
унитарные переходы, границы, все три текущие композиции, нативные события,
непрерывный прогноз без изменения модели, кеш и отмена подготовки.
`qa/scratch/browser.mjs` — Chromium/WebKit, выбор, перетаскивание, прогноз,
undo, три композиции до победы, старые головоломки. Chromium дополнительно
рендерит нативный Strudel в одном OfflineAudioContext: цель и состояние
с максимальной суммой квадратов множителей атак в плотном окне каждой песни.
Это выборочная акустическая проверка, не прослушивание всех 384 состояний.
`qa/scratch/touch.mjs` — портрет/ландшафт, commit/undo, cancel, пауза и смена
поля во время жеста. CDP touch Chromium и синтетические события WebKit
не заменяют физический iPhone/Safari.
