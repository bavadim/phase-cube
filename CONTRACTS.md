# Контракты музыкальной головоломки

Реализация: `puzzle-contract.js`, `composition-loader.js`, `session-loader.js`,
`controls/pattern-pieces.js`, `phase-map.js`, `music.js`. Единственный интерпретатор
нот и планировщик — закреплённый Strudel; правила кубика — cubejs. Нового
парсера мининотации или аудиодвижка нет.

## Модуль головоломки

Экспортирует `id`, `title`, `manifest`, `create()` и браузерный `mount(...)`.
Манифест находится рядом с правилами в `puzzles/<id>/module.js`:

```js
{
  schema: 'music-puzzle/3',
  id: 'twiddle',
  version: 2,
  projection: 'pose-phase/1',
  controls: 2,
  fragments: 6,
  pieceIds: [0, 1, 2, 3, 4, 5],
  poseIds: [0, 1, 2, 3, 4, 5],
  goalPolicy: 'single-reference'
}
```

Браузерный mount подключает `three-view.js` через общий `PuzzleControl`.
`PuzzleStage` владеет одним renderer/canvas, Raycaster, resize и GPU-ресурсами;
представление получает `invalidate()` для асинхронных текстур, возвращает геометрию
и смысл выбранного объекта, не подписывается
на DOM-ввод и не запускает собственный rAF. Музыкальная подготовка ниже не
зависит от камеры, графических объектов или компоновки страницы. Подробный
интерфейс представления — в README.md, раздел «Добавление представления».

Представление с внешним изображением возвращает необязательный `ready:Promise`.
Общий контрол передаёт его приложению: уровень остаётся в загрузке до получения
картинки. Ошибка и таймаут показываются пользователю; dispose завершает ожидание
отменённого представления. Загрузка изображения вызывает `invalidate()` общего
Stage; отдельного renderer или цикла анимации у представления нет.

Для прямого управления `hit` возвращает `key`, `pieceId` и `actionCenter`
(центр области в мировых координатах). Stage определяет направление по экранной
половине области; PuzzleControl хранит выбор первого нажатия и выполняет ход
при повторном. Жест перемещения и отменённый жест не выполняют ход. Подсказка
сразу подготавливает выбранную область к прямому повороту. Это состояние ввода,
оно не входит в манифест правил или музыкальную привязку.

`pieceIds` у `pose-phase/1` — последовательные числовые id от нуля. `poseIds` — уникальные
числа или строки. У Twiddle это шесть клеток, у кубика 24 пары `slot:orientation`.
Манифест не содержит музыкальных сдвигов. После изменения правил, проекции или
смысла id автор повышает `version`: это часть ключа кеша.

Модель, возвращаемая `create()`, реализует:

| Метод | Контракт |
| --- | --- |
| `create()` у модуля | Модель уже в опорном собранном состоянии; истории ходов и отмены пусты |
| `initialState()` | Новая копия опорного собранного состояния |
| `reset(seed)` | Вернуть опорное собранное состояние, очистить историю/подсказку и заново задать seed перемешивания |
| `shuffle()` | Сгенерировать и сразу применить ровно один допустимый ход, вернуть его id; один вызов — один ход |
| `legalMoves(state)` | Допустимые обратимые ходы для проверки |
| `applyTo(state, move)` | Новое состояние без изменения аргумента и живой модели |
| `inverse(move)` | Обратный ход |
| `placements(state)` | По одной записи `{pieceId, poseId}` на каждую деталь |
| `solved(state)` | Победа по правилам головоломки |
| `allStates()` | Необязательно: полный конечный граф для точной проверки |
| `goalStates()` | Необязательно: все принимаемые цели, включая их соседние переходы в проверку |

`shuffle()` вызывается последовательно, без предварительного скрытого
перемешивания. Одинаковые seed и число вызовов воспроизводят ту же цепочку.
Перемешивание не добавляет записи в `history`/`moves` игрока; `hint()` при этом
умеет решить полученное состояние (кубик хранит путь отдельно от истории отмены).
Генератор исключает собранные результаты и по возможности не повторяет область
предыдущего хода. У моделей с точным `distance(state)` первые короткие шаги
увеличивают расстояние до цели; число показанных шагов не является обещанием
точной сложности для произвольного числа перемешиваний.

```js
const model = puzzleModule.create(); // уже собрана
model.reset(1730);                   // собрана; seed для следующих вызовов
const before = model.snapshot();
const move = model.shuffle();        // модель изменилась ровно на один ход
await control.animate(move, before, {demonstration: true, duration: 200});
```

Это метод генерации одного хода, а не заранее вычисленный список и не JS-итератор:
следующее состояние возникает только при очередном вызове `shuffle()`.

Существующие snapshot/restore/apply/undo/hint/correct и выбор грани остаются
в моделях для игровой сессии и специфичного управления. Музыкального `phases()`
и `build()` в модуле больше нет. Интерфейс не вычисляет победу по звуковому совпадению.

### Показ перемешивания

Выбор пары ресурсов подготавливает собранное поле в состоянии `ready`.
Нажатие «Начать» включает звук непосредственно из доверенного события браузера
и переводит сессию в `shuffling`. Сначала видна и слышна цель, затем приложение
по одному вызывает `shuffle()`, анимирует возвращённую операцию и обновляет
музыкальную проекцию. Подсвечиваются область/направление и счётчик этапов;
кубик поворачивается к нужной грани. `animate(move, before, options)` получает
снимок до операции и необязательные `{demonstration, duration}`.
Быстрый показ трёх ходов занимает около секунды; визуальные шаги не ждут каждый
отдельной четверти аудио. Промежуточные звуковые проекции могут объединяться
планировщиком; финальная проекция применяется до выдачи управления игроку.

Пока идёт показ, пользовательские ходы, отмена, подсказка и перемотка заблокированы;
победа не проверяется. После последнего движения и звуковой транзакции —
`shuffle-complete` → `playing`, с пустой историей отмены. Продолжение с паузы
не перемешивает поле повторно. «Ещё раз» и новая пара ресурсов создают новый
собранный старт и новый показ. Смена ресурсов/выход отменяют старый показ;
при возврате из page cache продолжаются оставшиеся шаги. Reduced motion
сохраняет отдельные состояния и паузы между ними, без вращательной анимации.

`single-reference` использует прямую проекцию. `all-solved-to-reference` явно
задаёт прежнюю политику кубика: все 24 победные ориентации играют опорную цель.
Для несобранных состояний система отсчёта остаётся фиксированной. На финальном
переходе в повёрнутую цель могут измениться фазы всех игровых деталей; это
осознанное сохранение текущего поведения, не канонизация кадра после каждого
хода. Камера в проекции не участвует.

## Семейства головоломок и общий результат проекции

Все четыре модуля используют `music-puzzle/3`. Обязательные поля — `id`,
`version`, `projection`, `controls`, `fragments`, `goalPolicy`. `controls` — число
выбираемых областей (`choices()`), `fragments` — число музыкальных дорожек.
У Rubik это 6 граней и 8 фрагментов; у Twiddle — 2 группы и 6 фрагментов.
Ни количество деталей, ни тип проекции больше не выводятся из версии схемы.
Старые схемы и скрытые значения по умолчанию удалены.

`pose-phase/1` использует `pieceIds`, `poseIds`, `placements()` и таблицу сдвигов.
`complex-riff/2` — независимые фаза и уровень шести рифов.
`spectral-riff/1` — три детали картинки, каждая со своим неизменным рифом;
поворот меняет внутренний тайминг и акценты этого рифа, паз задаёт частоту
модуляции. Подробные формулы — в `puzzles/scratch/model.js` и
[описании пазла](docs/fourier-scratching.md).
В двух последних стратегиях нужен один орган управления на музыкальный фрагмент.

Для полярного Фурье: version 6, `projection:'complex-riff/2'`, `controls:6`,
`fragments:6`, `goalPolicy:'single-reference'`, `stateCount:139314069504`.
`model.count=6`: каждому музыкальному фрагменту соответствует один коэффициент.
Состояние — целое число из [0,139314069504), кодирующее шесть независимых пар
(фаза из 8, уровень из 9). Фазы в цели 0/45/135/180/225/315 градусов;
радиусы в цели равны 1. Цель имеет ID 0; исходные фразы калиброваны относительно
этих опорных фаз, так что исходный микс соответствует точному целевому состоянию.

Строки A/B/C/D/E/F вращают соответствующую фазу по часовой стрелке; штрих — против.
Суффиксы +/− меняют только радиус на одну ступень. Повороты имеют период 8,
радиус — ограниченный путь из девяти вершин: на границе операция недоступна,
обратный шаг всегда существует после допустимого. Все действия не образуют
единую группу глобальных перестановок. Частичные операции поддерживаются общим
контрактом legalMoves(state)/applyTo(state,move)/inverse(move).

Прямое редактирование задаётся JSON-объектом
`{kind:'coefficient',key,from:{phase,level},to:{phase,level}}`. from должен точно
совпадать с текущим коэффициентом; пустое или устаревшее изменение отклоняется.
Один жест — одна запись истории и одна музыкальная транзакция. Инверсия меняет
from/to местами. Выбор, подсказки, shuffle, undo и музыка не разбирают формат
хода: цель действия определяется через `moveTarget(move)`.

### Декларативные действия

Все модели обязаны реализовать `actions({perform,preview}={})`, возвращающий массив:

```js
{
 id:'turn-left', label:'Полное имя действия', icon:{text:'↶'}, // или {src:'assets/icon.png'}
 enabled:true, move, group:'Угол',
 onInvoke:()=>perform(move),
 onPreview:active=>preview(active?move:null)
}
```

Обязательны уникальный id, label, icon и onInvoke. enabled, group, move и
onPreview опциональны. `puzzles/actions.js` проверяет паспорт и создаёт callbacks
для ходов. Сам actions() не меняет модель; callbacks входят в общий диспетчер,
сохраняющий ограничения сессии, историю, звук, анимацию и победу.
`selectionLabel()` — необязательная подпись выбранного объекта.

`controls/action-controls.js` рисует кнопки по id: ceil(N/2) слева от подсказки,
остальные справа. Имена используются в aria-label/title, изображение создаётся
через img, текстовая иконка — через textContent. При обновлении сохраняются DOM
и клавиатурный фокус, удаляются устаревшие действия и обновляются callbacks/disabled.
Для narrow dock используется перенос групп, без проверки id головоломки.
Rubik/Twiddle возвращают два поворота, Фурье — два поворота и два шага радиуса.

### Единый фокус действия

`controls/action-focus.js` хранит `{source,key,move,owner?}`. Подсказка, область
поля, наведение кнопки, клавиатура и прямое перетаскивание входят в один контроллер.
Из его текущего значения получаются `view.feedback`, выделение `.action-focused`
и `music.predict(move)`. `.hinted` — совместимая метка того же фокуса для подсказки
и показа перемешивания, а не отдельное состояние. Настоящий DOM-фокус мышью
не перехватывается; Tab и Shift+Tab продолжают выбирать нативные кнопки.

Подсказка закрепляется; последнее наведение или клавиатурный фокус временно
перекрывает её. Выход возвращает закреплённую подсказку. Снятие фокуса имеет
владельца: запоздалый pointerleave старой кнопки не сбрасывает новую кнопку.
Пауза, ход, новая сессия и отмена взаимодействия очищают соответствующие источники;
устаревший ход перетаскивания и недоступные операции не восстанавливаются.

`view.hit()` может вернуть `move` для области действия. Прежний `actionCenter`
определяет левую/правую половину грани или группы через общий Stage. Мышь
выбирает и вооружает действие наведением; клик выполняет именно этот ход.
Touch не вооружает ход на pointerdown: первый тап выбирает, следующий вращает.
Представление может задать `hoverActions:false`, `requiresSelection:true` и
`selectionPrompt`. Так работает Фурье: пока наконечник/номер не выбран нажатием,
не выделяется коэффициент, не показывается его цель, кнопки операций недоступны.
Подсказка тоже явно выбирает коэффициент. Наведение на любую область Фурье не
меняет выбор и фокус, не вызывает `music.predict` и не перекрывает подсказку.
Невидимых зон поворота/изменения радиуса нет. При перетаскивании `onEditPreview`
задаёт точную правку выбранного коэффициента; звук и модель до отпускания сохраняются.
Нижние кнопки и их клавиатурный фокус после выбора работают как прежде.

Проекция `complex-riff/2` независима по рифам. Один коэффициент меняет только
свой риф. При переходе в ту же дискретную ячейку прогноз не пересоздаётся.

### Эквалайзер событий

Музыкальные события получают стабильные визуальные `id` в `targetRows`.
Они сохраняются при фазовых сдвигах и Fourier-сортировке, не добавляясь к значениям
семплов или планировщику Strudel. Эквалайзер группирует одновременные атаки,
переиспользует DOM-узлы и анимирует их по кратчайшей дуге за 300 мс, включая
стык цикла. Повторная установка того же фокуса не перезапускает переход.
Reduced motion сразу показывает конечное состояние.

Гнёзда цели находятся на радиусах текущих событий; второй целевой дорожки и
пунктирного слоя прогноза нет. При совпадении партии гнёзда скрываются под
собранным рисунком. Сетка содержит границы тактов без мелких подразделений,
легенды в интерфейсе нет. Длительность дуги — gate события, не хвост PCM-семпла.

Только локальный маркер начала атаки вспыхивает на 120 мс; вся партия не пульсирует.
Во время прогноза/перехода эти вспышки отключены, локатор продолжает показывать
музыкальную позицию, звук прогнозом не меняется. Подтверждение удерживает прогноз
до применения соответствующей аудиотранзакции, без отскока к предыдущей позиции.
В `complex-riff/2` модуль меняет реальный gain рифа (0–200% с шагом 25%), умножая его
на авторский postgain события после обработки тембра. Цвет сохраняет hue/saturation, а HSV value монотонно
растёт с velocity × уровнем рифа; толщина штриха служит дополнительным признаком.
У выбранного рифа показан относительный уровень в процентах. Это не LUFS-метр и не
сравнение акустической громкости разных тембров. Прогноз анимирует уровень и
время тех же DOM-событий, без затемнения других дорожек. Fingerprint включает
уровень, поэтому чистое изменение громкости удерживается до аудиокоммита.

Оборот единственного локатора соответствует `song.periodBars` на общем темпе.
Минимальный период рифа определяется точным совпадением мультимножества атак,
нот, тембров, gate и динамики при циклическом сдвиге. Он является долей общего
цикла, не отдельным темпом. Все повторы показаны на общей шкале времени;
поворот коэффициента на 45° сдвигает его риф на ⅛ собственного периода.
На выбранной дорожке засечки повторов двигаются вместе с рисунком, локатор
двигается только по музыкальным часам. При прогнозе засечки относятся к прогнозу;
во время неподтверждённой правки звук и часы остаются исходными.

Проверки фокуса и сохранения узлов: `node --test test-focus.cjs`,
`node qa/focus/browser.mjs` в Chromium и WebKit. Физический Safari остаётся
отдельной проверкой, браузерная эмуляция не является её заменой.

### Жесты и музыкальная проекция

View дополнительно может поддерживать beginDrag(hit,world), dragTo(world),
endDrag(cancelled). Hit отмечает draggable. Общий Pointer определяет начало
жеста после порога, Stage переводит координаты в мировую плоскость и передаёт
их представлению. endDrag возвращает ход; Stage передаёт его в тот же onMove.
Canvas имеет одну подписку; Rubik продолжает использовать drag(dx,dy) для камеры.
Cancel/blur/lost capture/pause/смена поля отбрасывают незавершённый прогноз.

Фурье рисует шесть стрелок и кольца уровня 100% и 200% на общей плоскости. Пустой
круг — цель выбранного коэффициента. Наконечники выбираются и перетаскиваются;
шесть постоянных номерных меток выбирают коэффициент при совпадении наконечников.
Во время drag модель и звук сохраняют исходный снимок. onEditPreview обновляет
прогноз эквалайзера. После отпускания угол и радиус округляются к сетке; перед
onMove снимается захват, чтобы общий busy-gate не отменил собственный коммит.

Обе стратегии возвращают `music-projection/1` с native Strudel patterns, rows и
parts. Количество соответствует музыкальным fragments. `pose-phase/1` сохраняет
ticks/offset. Для `complex-riff/2` параметры рифа i:

```
z_i = a_i exp(i φ_i), a_i ∈ {0, ¼, ½, ¾, 1, 1¼, 1½, 1¾, 2}
δ_i = wrap(φ_i − φ_goal_i) / (2π)
t'_event = (t_event − δ_i P_i) mod 1
postgain'_event = postgain_event × a_i
```

`P_i` — минимальный период рифа в единицах общего цикла. Поворот и положительное
масштабирование коммутируют; поворот имеет порядок 8. Это диагональное действие
комплексных управляющих коэффициентов на периодические фразы, а не преобразование
Фурье PCM. Ноль допускается, фаза в нуле хранится отдельно; кнопки ±¼ являются частичными операциями, а не комплексным умножением.
Ноты, тембры, velocity, gate и число событий сохранены. В цели используются
исходные Pattern; фон и Strudel-транспорт остаются общими. Результат вычисляется
из состояния и авторского образца, а не накоплением ошибок по истории ходов.

Подготовка использует ограниченные воспроизводимые пробы, включая все 72 значения
каждого коэффициента отдельно. Она не обходит все 139 314 069 504 состояний на телефоне.
coverage=sampled явно записывается в отчёт. Сигнатура проверяет отдельные рифы,
а не сумму PCM; взаимная компенсация одинаковых тембров в итоговом миксе этим
не исключена. Отсутствие символических коллизий на выборке не доказывает
глобальную акустическую различимость. Музыкальная приёмка остаётся unverified.

Ключ кеша включает семейство/версию стратегии, манифест головоломки и анализ
композиции. При изменении правил или опорных коэффициентов поднять version.
Манифесты композиций `music-composition/1` не изменены. Предыдущие семейства
fourier-time/1, /2 и /3 и их ID не воспроизводятся текущим модулем.

## Модуль композиции

Обычный ES-модуль экспортирует `metadata` и `default compose(S)`. В metadata
обязательны `schema: 'music-composition/1'`, положительный целый `version`,
название, стиль и BPM. Фабрика возвращает metadata плюс `sections`, `periodBars`,
`backing` и непустой `playerParts`. Поддерживаемый размер v1 — 4/4; другой размер
отклоняется, поскольку текущий транспорт использует четыре четверти на цикл.

Загрузчик выводит `timing` с `periodBeats`/`songBeats` в четвертных долях,
секции, длительность, инструменты и число событий. Strudel-циклы используются
только в адаптерах. Полный фон и игровые партии повторяются в своих масштабах:
плеер использует полную песню, круг — период игровых партий.

Игровая партия задаёт `key`, `name`, `pattern`. Необязательные поля:

- `weight`: относительная доля деталей. Прежнее `pieces` принимается как вес.
- `split: 'time'`: разбиение на равные временные окна; пустая деталь — ошибка.
- `groups: [{onsetsBeats: [0, 2, 4]}, ...]`: неделимые авторские фразы.
  Все уникальные моменты атак периода должны быть покрыты ровно один раз.
  Аккорд на общей атаке всегда сохраняется целиком. Группы нельзя сочетать с time.

Без групп атаки распределяются по очереди. Загрузчик распределяет нужное число
деталей с учётом весов и доступных групп. Если групп недостаточно, пара
несовместима: ограничения не ослабляются. Составление деталей сохраняет все
события ровно один раз, включая высоту, gate, динамику и параметры звука.

Композиция может указать `phaseOptions: {subdivisionsPerBeat: [2, 4]}` —
допустимые сетки сдвига (по умолчанию восьмые/шестнадцатые). Разрешено до четырёх
целых значений 1–8. Число деталей и положения конкретной головоломки ей неизвестны.

## Общая привязка

`analyzePattern(events, periodBeats)` извлекает события и точные ритмические
симметрии. `fitPhaseMap({puzzle, game, analysis, subdivisions, signal})`
анализирует весь набор деталей, сохраняя их принадлежность инструментам:
замена одной ноты другой в том же инструменте не выдаётся за новый ритм.

Для каждой сетки проверяется до шести детерминированных таблиц: упакованная,
несколько перестановок шага, равномерная и фиксированная псевдослучайная.
Максимум — 24 кандидата, по умолчанию 12. Разные положения обязаны иметь разные
фазы; слишком тесная сетка отклоняется. Подбор уступает управление UI между
кандидатами и поддерживает AbortSignal.

Для Twiddle проверяются все 120 состояний и 240 неориентированных рёбер.
Для кубика проверяются все 24 цели с соседями и ограниченный детерминированный
случайный обход (до 192 шагов, до 384 рёбер). Это выборка, а не полный кубик.
На проверенных переходах также проверяется точное восстановление обратным ходом.

Критерии выбора по приоритету:

1. Меньше несобранных состояний с целевым ритмом.
2. Меньше ходов без ритмических изменений.
3. Меньше неожиданных совпадений ритмов состояний; эквивалентные цели разрешены.
4. Короче максимальный круговой промежуток без различающихся атак.
5. Больше минимальная, затем средняя доля различающихся событий на ход.

`projectMusic(binding, puzzle, state)` — чистое применение выбранной таблицы:

```text
ticks = mod(table[currentPose] - table[referencePose], gridSteps)
offsetBeats = ticks * periodBeats / gridSteps
```

`music.js` переводит эти величины в точные Fraction для Strudel `.late()`.
Эквалайзер, прогноз и реальное воспроизведение используют ту же проекцию.
Привязка неизменна на протяжении игры и не зависит от пути к состоянию.

## Подготовка и кеш

`new PuzzleSessionLoader.Loader(S, {registry, palette, library, preload, storage})`
вызывает `prepareSession({songId, puzzleId, signal})` и возвращает:

```js
{composition, module, model, puzzle, fragments, binding, analysis, stats, diagnostics}
```

Загрузка композиции, проверка контрактов, разбиение, подбор и предзагрузка банков
заканчиваются до установки новой сессии. При быстрой смене выбора предыдущая
подготовка отменяется; устаревший результат не монтирует интерфейс.

Ключ кеша — SHA-256 от музыкального анализа с параметрами звука, принадлежности
фрагментов партиям, манифеста/проекции цели, сеток и версии алгоритма. Изменение
методов правил требует повышения версии манифеста; изменение алгоритма — его
версии. В памяти кешируются готовые таблицы, в localStorage — последние 12.
Каноническое поле результата — `binding`; прежний `phaseMap` удалён.
Новый кеш — `music-puzzle-bindings/3`. При недоступности storage или Web Crypto игра работает без постоянного кеша.
Повреждённая таблица с совпадающими фазами отвергается. Частичный результат
отменённого поиска не сохраняется.

`diagnostics` разделяет `coverage: complete|sampled`, численные совпадения,
`discrimination: weak|distinct-in-probes`, задержку обратной связи и
`acousticAcceptance: unverified`. Порог двух долей — диагностический ориентир
задержки, не сертификат музыкального качества. Например, исходная временная
нарезка «Цеха» содержит длинные паузы: подбор может улучшить различимость,
но не устраняет это ограничение композиции. Маскировка фоном, реальные хвосты
семплов и слуховая приёмка этим анализом не проверяются.

Проверки: `test-bindings.cjs`, общий браузерный прогон и автономный экспорт.
Численные результаты всех шести сочетаний — `qa/contracts/report.json`.

### Непрерывная правка и ноты (continuous2)

`onEditPreview(move, point)` передаёт непрерывные `{key, phase, gain}` отдельно
от округлённого хода. `Music.preview()` строит только визуальный прогноз;
эквалайзер применяет его сразу, без повторного 300-мс догоняющего перехода.
Фаза и уровень меняются даже внутри одной ячейки привязки. Отпускание сохраняет
один ход на сетке 45° / 25%; пустой жест не попадает в историю. Фаза сохраняется
при нулевом радиусе; кнопка «+» поднимает уровень из нуля до 25%.

`pitch` — визуальная метаданная native-события, не параметр аудиодвижка.
В пределах дорожки радиальное положение отметки отражает высоту ноты;
гнездо цели использует ту же шкалу. Одинаковые атаки с разными нотами теперь
дают разные контуры. Победа требует исходных нот и уровня 100%; фазы,
отличающиеся на целые обороты, нормализуются до сравнения. Шаблон только
ритма не является достаточным условием победы. Ключ кеша привязки включает
полные исходные значения нот и патчей, чтобы смена нот при том же ритме
не переиспользовала старые периоды.
