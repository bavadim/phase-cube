# Контракты музыкальной головоломки

Реализация: `puzzle-contract.js`, `composition-loader.js`, `session-loader.js`,
`controls/pattern-pieces.js`, `phase-map.js`, `music.js`. Единственный интерпретатор
нот и планировщик — закреплённый Strudel; правила кубика — cubejs. Нового
парсера мининотации или аудиодвижка нет.

## Модуль головоломки

Экспортирует `id`, `title`, `manifest`, `create()` и браузерный `mount(...)`.
Манифест находится рядом с правилами в `puzzles/<id>/module.js`:

```js
{
  schema: 'music-puzzle/1',
  id: 'twiddle',
  version: 1,
  pieceIds: [0, 1, 2, 3, 4, 5],
  poseIds: [0, 1, 2, 3, 4, 5],
  goalPolicy: 'single-reference'
}
```

Браузерный mount подключает `three-view.js` через общий `PuzzleControl`.
`PuzzleStage` владеет одним renderer/canvas, Raycaster, resize и GPU-ресурсами;
представление возвращает геометрию и смысл выбранного объекта, не подписывается
на DOM-ввод и не запускает собственный rAF. Музыкальная подготовка ниже не
зависит от камеры, графических объектов или компоновки страницы. Подробный
интерфейс представления — в README.md, раздел «Добавление представления».

Для прямого управления `hit` возвращает `key`, `pieceId` и `actionCenter`
(центр области в мировых координатах). Stage определяет направление по экранной
половине области; PuzzleControl хранит выбор первого нажатия и выполняет ход
при повторном. Жест перемещения и отменённый жест не выполняют ход. Подсказка
сразу подготавливает выбранную область к прямому повороту. Это состояние ввода,
оно не входит в манифест правил или музыкальную привязку.

`pieceIds` в v1 — последовательные числовые id от нуля. `poseIds` — уникальные
числа или строки. У Twiddle это шесть клеток, у кубика 24 пары `slot:orientation`.
Манифест не содержит музыкальных сдвигов. После изменения правил, проекции или
смысла id автор повышает `version`: это часть ключа кеша.

Модель, возвращаемая `create()`, реализует:

| Метод | Контракт |
| --- | --- |
| `initialState()` | Новая копия опорного собранного состояния |
| `legalMoves(state)` | Допустимые обратимые ходы для проверки |
| `applyTo(state, move)` | Новое состояние без изменения аргумента и живой модели |
| `inverse(move)` | Обратный ход |
| `placements(state)` | По одной записи `{pieceId, poseId}` на каждую деталь |
| `solved(state)` | Победа по правилам головоломки |
| `allStates()` | Необязательно: полный конечный граф для точной проверки |
| `goalStates()` | Необязательно: все принимаемые цели, включая их соседние переходы в проверку |

Существующие snapshot/restore/reset/apply/undo/hint/correct и выбор грани остаются
в моделях для игровой сессии и специфичного управления. Музыкального `phases()`
и `build()` в модуле больше нет. Интерфейс не вычисляет победу по звуковому совпадению.

`single-reference` использует прямую проекцию. `all-solved-to-reference` явно
задаёт прежнюю политику кубика: все 24 победные ориентации играют опорную цель.
Для несобранных состояний система отсчёта остаётся фиксированной. На финальном
переходе в повёрнутую цель могут измениться фазы всех игровых деталей; это
осознанное сохранение текущего поведения, не канонизация кадра после каждого
хода. Камера в проекции не участвует.

## Семейства головоломок и общий результат проекции

Прежний `music-puzzle/1` остаётся контрактом размещения деталей с фазовой
проекцией. Он не выражает смешивание независимых комплексных коэффициентов:
сдвиг времени умножает гармонику k на exp(−2πikδ), а общий унитарный оператор
может смешивать гармоники. Одинаковая группа для этих операций не заявляется.

Для Фурье-печати добавлен `music-puzzle/2`:

```js
{schema:'music-puzzle/2', id:'fourier', version:1,
 projection:'fourier-time/1', fragments:6, goalPolicy:'single-reference',
 operations:{A:4, B:4, M:8}, stateCount:192}
```

Число музыкальных `fragments` отделено от `model.count`: у печати шесть звуковых
деталей и два коэффициента, по которым считается прогресс. Нативные состояния,
переходы, обратные операции, цель и подсказки принадлежат модулю головоломки.
Сдвиговые модули сохраняют placements и прежние музыкальные таблицы.
`moveTarget(move)` сообщает общему управлению выбранную часть без разбора строки
хода в приложении. Необязательный `actionLabel(key, inverted)` описывает операцию.

`music-projection.js` выбирает отдельную стратегию подготовки и проверки кеша.
Результат `project(S, prepared, state)` для обеих стратегий — `music-projection/1`:

```js
{schema:'music-projection/1', patterns:[/* native Strudel Pattern */],
 rows:[/* start, duration, value */], parts:[{kind, id, aligned, /* optional ticks */}]}
```

Количество patterns/rows/parts равно числу музыкальных фрагментов. В цели
используются исходные паттерны. Звук и эквалайзер берут одну проекцию. У сдвиговой
стратегии есть ticks/offset; у нелинейной их нет. Эквалайзер использует aligned и
фактические события, не выдумывает фазу нелинейному преобразованию.
Историческое имя `prepared.phaseMap` пока обозначает binding обеих стратегий;
поле algorithm различает `pose-phase/1` и `fourier-time/1`.

Групповой закон задаётся на состояниях головоломки. Проекция — чистая функция
состояния и исходной композиции: звук не зависит от истории ходов. Не требуется,
чтобы обычная композиция двух временны́х warp-функций повторяла умножение матриц.
Каждый новый паттерн пересчитывается от авторского образца. Для Фурье-печати
различимость всех 192 проекций проверяется отдельно; на этом конечном семействе
ходы задают обратимые преобразования через ID состояния. Это не универсальная
алгебра преобразований произвольных Strudel-паттернов.

Фурье-печать использует два коэффициента и операторы A: diag(i,1),
B: diag(1,i), M: [[1,−1],[1,1]]/√2. Замыкание содержит 192 матрицы. Матрицы
идентифицируются численно при построении; ходы применяются по точной таблице
целочисленных ID. Полный граф даёт обратимость и кратчайшие подсказки. A/B имеют
период 4, M — 8; ограничение «каждый ход повторяется четыре раза» в общий контракт
не входит. Тесты проверяют норму, периоды и обратимость на всех состояниях.

Декодирование меняет только время атак через ограниченную сумму двух гармоник.
Граница производной смещения < 1 сохраняет циклический порядок внутри каждой
детали. При ненулевом состоянии конечный событийный атлас выпускает native
Strudel Hap/TimeSpan через Pattern.query; отдельного планировщика или синтезатора
нет. Проверяется совпадение рассчитанных событий с queryArc, включая переход
через границу периода, продолжения нот и clip. В цели возвращаются исходные
Pattern. Ноты, тембры, динамика, длительности и число событий сохраняются.
Это не гарантия гармоничности относительно неподвижного фона.

Манифест композиции `music-composition/1` не изменён: конечный повторяющийся
набор событий уже проверяется загрузчиком. Фон, транзакции транспорта, Web Audio,
сохранение MP3 и экспорт страницы общие. Ключ кеша включает семейство стратегии,
её версию, манифест головоломки и музыкальный анализ; binding другой стратегии
или изменённой композиции не переиспользуется.

Исходный референс, точная формула и границы первой реализации сохранены в
`docs/fourier-seal/`. Отчёты — `qa/fourier/`.
Символьная различимость проверяется по полному графу для каждой композиции;
акустическая и музыкальная приёмка остаются unverified.

## Модуль композиции

Обычный ES-модуль экспортирует `metadata` и `default compose(S)`. В metadata
обязательны `schema: 'music-composition/1'`, положительный целый `version`,
название, стиль и BPM. Фабрика возвращает metadata плюс `sections`, `periodBars`,
`backing` и непустой `playerParts`. Поддерживаемый размер v1 — 4/4; другой размер
отклоняется, поскольку текущий транспорт использует четыре четверти на цикл.

Загрузчик выводит `timing` с `periodBeats`/`songBeats` в четвертных долях,
секции, длительность, инструменты и число событий. Strudel-циклы используются
только в адаптерах. Полный фон и игровые партии повторяются в своих масштабах:
плеер использует полную песню, круг — период игровых партий.

Игровая партия задаёт `key`, `name`, `pattern`. Необязательные поля:

- `weight`: относительная доля деталей. Прежнее `pieces` принимается как вес.
- `split: 'time'`: разбиение на равные временные окна; пустая деталь — ошибка.
- `groups: [{onsetsBeats: [0, 2, 4]}, ...]`: неделимые авторские фразы.
  Все уникальные моменты атак периода должны быть покрыты ровно один раз.
  Аккорд на общей атаке всегда сохраняется целиком. Группы нельзя сочетать с time.

Без групп атаки распределяются по очереди. Загрузчик распределяет нужное число
деталей с учётом весов и доступных групп. Если групп недостаточно, пара
несовместима: ограничения не ослабляются. Составление деталей сохраняет все
события ровно один раз, включая высоту, gate, динамику и параметры звука.

Композиция может указать `phaseOptions: {subdivisionsPerBeat: [2, 4]}` —
допустимые сетки сдвига (по умолчанию восьмые/шестнадцатые). Разрешено до четырёх
целых значений 1–8. Число деталей и положения конкретной головоломки ей неизвестны.

## Общая привязка

`analyzePattern(events, periodBeats)` извлекает события и точные ритмические
симметрии. `fitPhaseMap({puzzle, game, analysis, subdivisions, signal})`
анализирует весь набор деталей, сохраняя их принадлежность инструментам:
замена одной ноты другой в том же инструменте не выдаётся за новый ритм.

Для каждой сетки проверяется до шести детерминированных таблиц: упакованная,
несколько перестановок шага, равномерная и фиксированная псевдослучайная.
Максимум — 24 кандидата, по умолчанию 12. Разные положения обязаны иметь разные
фазы; слишком тесная сетка отклоняется. Подбор уступает управление UI между
кандидатами и поддерживает AbortSignal.

Для Twiddle проверяются все 120 состояний и 240 неориентированных рёбер.
Для кубика проверяются все 24 цели с соседями и ограниченный детерминированный
случайный обход (до 192 шагов, до 384 рёбер). Это выборка, а не полный кубик.
На проверенных переходах также проверяется точное восстановление обратным ходом.

Критерии выбора по приоритету:

1. Меньше несобранных состояний с целевым ритмом.
2. Меньше ходов без ритмических изменений.
3. Меньше неожиданных совпадений ритмов состояний; эквивалентные цели разрешены.
4. Короче максимальный круговой промежуток без различающихся атак.
5. Больше минимальная, затем средняя доля различающихся событий на ход.

`projectMusic(binding, puzzle, state)` — чистое применение выбранной таблицы:

```text
ticks = mod(table[currentPose] - table[referencePose], gridSteps)
offsetBeats = ticks * periodBeats / gridSteps
```

`music.js` переводит эти величины в точные Fraction для Strudel `.late()`.
Эквалайзер, прогноз и реальное воспроизведение используют ту же проекцию.
Привязка неизменна на протяжении игры и не зависит от пути к состоянию.

## Подготовка и кеш

`new PuzzleSessionLoader.Loader(S, {registry, palette, library, preload, storage})`
вызывает `prepareSession({songId, puzzleId, signal})` и возвращает:

```js
{composition, module, model, puzzle, fragments, phaseMap, analysis, stats, diagnostics}
```

Загрузка композиции, проверка контрактов, разбиение, подбор и предзагрузка банков
заканчиваются до установки новой сессии. При быстрой смене выбора предыдущая
подготовка отменяется; устаревший результат не монтирует интерфейс.

Ключ кеша — SHA-256 от музыкального анализа с параметрами звука, принадлежности
фрагментов партиям, манифеста/проекции цели, сеток и версии алгоритма. Изменение
методов правил требует повышения версии манифеста; изменение алгоритма — его
версии. В памяти кешируются готовые таблицы, в localStorage — последние 12.
При недоступности storage или Web Crypto игра работает без постоянного кеша.
Повреждённая таблица с совпадающими фазами отвергается. Частичный результат
отменённого поиска не сохраняется.

`diagnostics` разделяет `coverage: complete|sampled`, численные совпадения,
`discrimination: weak|distinct-in-probes`, задержку обратной связи и
`acousticAcceptance: unverified`. Порог двух долей — диагностический ориентир
задержки, не сертификат музыкального качества. Например, исходная временная
нарезка «Цеха» содержит длинные паузы: подбор может улучшить различимость,
но не устраняет это ограничение композиции. Маскировка фоном, реальные хвосты
семплов и слуховая приёмка этим анализом не проверяются.

Проверки: `test-bindings.cjs`, общий браузерный прогон и автономный экспорт.
Численные результаты всех шести сочетаний — `qa/contracts/report.json`.
