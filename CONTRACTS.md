# Контракты и границы компонентов

Игра использует `music-puzzle/3`, композиция — `music-composition/1`, результат
музыкальной проекции — `music-projection/1`. Их реализации находятся в
`puzzle-contract.js`, `composition-contract.js` и `music-projection.js`.
Strudel интерпретирует музыку и планирует звук; Three.js отображает головоломки.

## Игра

`puzzles/<id>/module.js` экспортирует `id`, `title`, `manifest`, `create()`.
Дополнительно допускаются `progressLabel`, `shuffleSteps`,
`configure(S, composition, options)` для собственной нарезки музыки.
Модуль не импортирует DOM, renderer, контролы или загрузчик композиций.
Подключение вида выполняется отдельно через `graphics/puzzle-views.js`.

Обязательные поля манифеста: `schema`, `id`, `version`, `projection`, `controls`,
`fragments`, `goalPolicy`. Число `controls` совпадает с `choices().length`;
`fragments` задаёт число музыкальных дорожек. Изменение правил/проекции/id повышает
`version`, которая входит в отпечаток музыкальной привязки.

Поддерживаются:

| Проекция | Игры | Данные |
| --- | --- | --- |
| `pose-phase/1` | Rubik, Twiddle | Положения деталей и заранее проверенная таблица фаз |
| `complex-riff/3` | Fourier, Bounce | Шесть независимых рифов: фаза C8 и непрерывная громкость 0–2 |
| `spectral-riff/2` | Scratch | Все партии композиции нарезаются на подвижные плитки; поворот и перестановка меняют музыкальную проекцию |

`pose-phase/1` дополнительно объявляет `pieceIds`, `poseIds` и `placements()`.
Политика `single-reference` использует одну цель. `all-solved-to-reference`
позволяет всем 24 собранным ориентациям кубика воспроизводить ту же авторскую
цель; камера не влияет на музыкальное состояние.

Модель предоставляет:

| Методы | Обязательства |
| --- | --- |
| `initialState`, `snapshot`, `reset(seed)` | Новая модель и reset собраны; reset очищает историю и задаёт seed |
| `shuffle()` | Применить один допустимый ход и вернуть его; не добавлять его в историю игрока |
| `legalMoves`, `validMove`, `applyTo`, `inverse` | Чистое вычисление следующего состояния и обратного хода |
| `apply`, `undo` | Изменение живой модели с историей и точным возвратом |
| `solved`, `correct`, `hint` | Победа, прогресс и допустимая подсказка по правилам игры |
| `choices`, `select`, `moveFor`, `moveTarget` | Выбор игрового объекта независимо от рендерера |
| `actions(callbacks)` | Действия с уникальными id, названием, иконкой, enabled и callback; callback передаёт ход общему диспетчеру |
| `editPoint(key, {phase, gain}, before)` | Для `complex-riff/3`: ближайшая дискретная фаза и исходная непрерывная громкость; один защищённый ход либо null |

`applyTo` не меняет аргумент или модель. Обратный ход восстанавливает исходное
состояние. `hint()` должен решать состояние после перемешивания. Подсказка,
выбор и прогноз не добавляют ходы. Частичные жесты остаются вне состояния;
отпускание фиксирует один ход, отмена возвращает состояние до жеста.

`manifest.interaction` задаёт `requiresSelection`, `allowDeselect`,
`hoverActions`, `buttonPreview`, `selectionPrompt`. Общий контракт проверяет типы
и подставляет значения по умолчанию. Представления не дублируют эти флаги.

## Композиция

`compositions/catalog.js` — список доступных id ресурсов. Каждому соответствует
`compositions/<id>.strudel.mjs` с двумя экспортами:

```js
export const metadata = {
  schema: 'music-composition/1', version: 1,
  title: 'Название', style: 'Стиль', bpm: 150,
  download: 'assets/track-game.mp3'
};
export default function compose(S) {
  return {
    ...metadata, meter: [4, 4], periodBars: 4,
    sections: [{name: 'Основная', bars: 16}],
    playerParts: [{key: 'lead', name: 'Мелодия', pattern: S.note('c4 e4 g4 e4 g4 e4 d4 c4').s('sine').slow(4)}],
    backing: S.silence
  };
}
```

`composition-contract.js` проверяет паспорт модуля, затем скомпилированную
композицию. Требуются положительный BPM, непустая форма, целое число игровых
периодов в форме, уникальные ключи партий, непустые повторяющиеся партии и фон.
Текущий транспорт поддерживает 4/4. Ноты сохраняют нативные Strudel-параметры,
тайминг, длительности, динамику и тембры; собственного парсера мининотации нет.

Дополнительные `weight`, `pieces`, `groups` партии описывают ограничения её
разделения на фрагменты. Они не содержат граней кубика, экранных координат или
DOM-контролов. Музыка не знает, какая головоломка будет её воспроизводить.

Контракт возвращает исходные музыкальные данные, общий Pattern, границы секций,
`timing` и вычисленную `stats`. `attacks`, `eventsOf`, `signature` анализируют
нативные события и доступны музыкальным адаптерам без импорта загрузчика.

`composition-loader.js` отвечает только за импорт модулей, ленивый каталог и
кеш. `catalog()` читает паспорта без вызова `compose`; `load(id)` вызывает
композиторскую функцию и контракт. Имена и музыкальные параметры не копируются
в конфиг игры. Для автономного HTML используются те же фабрики композиций и
семплы, встроенные `export.mjs`.

## Подготовленная сессия и звук

`session-loader.js` соединяет независимо выбранные `songId` и `puzzleId`:

1. Загружает и проверяет композицию и модель игры.
2. Получает нарезку через `configure` либо общий `PuzzleParts.build`.
3. Вычисляет или проверяет кешированную музыкальную `binding`.
4. Возвращает `{composition, module, model, puzzle, fragments, binding, analysis, diagnostics}`.

Кеш зависит от контракта игры и фактических музыкальных событий. Изменение нот
или правил не переиспользует неподходящую привязку. Отменённая подготовка не
сохраняет частичный результат.

`music-projection.js` преобразует состояние модели в `{parts, rows, patterns}`
через выбранную стратегию. `rows` содержат нормализованные время начала,
длительность, высоту, динамику и нативное значение звука. `music.js` кеширует
проекции и вычисляет прогнозы; `transport.js` владеет аудиочасами, применением
транзакций, паузой и перемоткой. В музыкальных компонентах нет renderer или DOM.

## Представление и контролы

`puzzles/<id>/three-view.js` экспортирует `create(context)`; реестр
`graphics/puzzle-views.js` сопоставляет id правилам отображения. Представление
получает `scene`, `resources`, `model`, `game`, `binding`, `tween`, `onEditPreview`.
Его обязательные методы: `camera`, `resize`, `sync`, `pickTargets`, `hit`,
`locations`, `feedback`, `animate`. `puzzle-contract.js` проверяет этот интерфейс.

Необязательные возможности: `ready` для текстуры, `dispose`, `focus`, `drag`
для камеры, `inputPlane`, `updateMusic`. Жест редактирования реализуется тройкой
`beginDrag`, `dragTo`, `endDrag(cancelled)`; последний возвращает ход, а не меняет
модель. `pressable` в результате hit начинает жест сразу при нажатии.
`updateMusic` получает циклическую фазу и монотонную позицию аудиотранспорта;
время не вычисляется отдельным игровым таймером.

`PuzzleStage` владеет одним canvas/renderer, Raycaster, захватом указателя,
анимациями, resize и очисткой ресурсов. Представление не создаёт собственный
renderer, rAF, DOM-кнопки или обработчики мыши. Геометрия регистрируется через
`resources`; при смене игры она освобождается.

`controls/puzzle.js` владеет выбором, фокусом действия и правилами первого/повторного
тапа. `controls/action-controls.js` строит кнопки по actions модели и добавляет
общий выбор следующего объекта. `controls/hint.js`, `player.js`, `dialogs.js`
отвечают соответственно за подсказку, транспортную панель и диалоги. Решение
головоломки, допустимые ходы и музыка в этих компонентах не определяются.

## Эквалайзер

`controls/equalizer.js/.css` — отдельный компонент. Он получает только
`{rows, target, phases, forecast, selectedKey, pending}` через `update` и время
через `frame`. Число дорожек берётся из фрагментов композиции. Он показывает
текущие события, гнёзда цели, громкость, локатор и анимированный прогноз.
Эквалайзер не загружает музыку, не знает правил Rubik/Fourier/Bounce и не
применяет ходы. Для него у всех головоломок используется одна разметка.

`app.js` только соединяет ресурсы и компоненты, проводит жизненный цикл сессии
и передаёт ходы/данные между ними. В нём нет рисования фигур или музыкальных нот.

## Проверка

`npm run check`, `test-components.cjs`, `test-compositions.cjs`, `test-bindings.cjs`,
`test-fourier.cjs`, `test-scratch.cjs`, `test-bounce.cjs` проверяют границы,
нативные события, игровые операции и музыкальные привязки. Браузерные проверки
в `qa/` проверяют контролы, выбор ресурсов, эквалайзер, мышь/тач и автономный HTML.
Отчёты содержат отпечатки конкретных исходников. Структурный PASS и WebKit-эмуляция
не заменяют музыкальную приёмку или проверку на физическом iPhone.
