# Музыкальный диск — прототип на трёх партиях

Открыть `disc/index.html` через HTTP из корня `experiments/steel-shift-cube`.
Это отдельный эксперимент; прежняя машина и головоломки сохранены.

## Музыкальное соответствие

Используются ровно три исходные партии «Моцарта на конвейере»: `kick`, `bass`,
`hook`. Начальное окно — такты 8–12 при нумерации с нуля. Ноты, звуковые патчи,
длительности и динамика берутся из нативных Strudel-событий. Остальные голоса
и прежний фон не звучат.

- Полный оборот — четыре такта, 6,4 секунды при 150 BPM.
- Все кольца вращаются по одному аудиотранспорту.
- Радиальная дорожка обозначает партию. Угол события — его время.
- Передний край отметки проходит неподвижную линию считывания в момент атаки.
- Дуга обозначает длительность события. Она не измеряет хвост эффектов.
- Рельеф показывает динамику с учётом усиления выбранной партии.
- Цвет дорожки обозначает партию; различия нот дополнительно видны на вставках.

Кольцо можно повернуть независимо. Фаза хранится в долях **полного цикла**:
`late(phase * periodBars)`. Во время перетаскивания возможна непрерывная проба;
отпускание фиксирует ближайший из 32 шагов (восьмая нота). Полный поворот
тождествен исходному состоянию. Усиление — 0…2, без изменения высот и времени.
Выключение сохраняет настройку и рисунок. У фортепиано четыре исходные фразы;
одинаковые варианты бочки/баса не дублируются.

Сдвиги разных гармонических партий могут менять созвучия. Прототип не
оценивает музыкальную правильность и не обещает благозвучие любого сочетания.
Цель — проверить читаемость связи между движением детали и изменением звука.

## Управление и хранение

Настройки находятся на модели: обод для фазы, захват рельефа для усиления,
головка считывателя для включения, картридж фортепиано для смены фразы.
Отдельный клик по кольцу выбирает его. Жест мышью и жест пальцем используют
общий Pointer-контрол. Отмена возвращает целый жест, cancel не сохраняет его.

На основном экране только воспроизведение и отмена. Меню содержит A/B,
сохранение, восстановление и перенос сборки JSON. Есть автосохранение.
Экспорт сборки не является экспортом аудио.

## Границы модулей

| Файл | Ответственность |
| --- | --- |
| `model.js` | `disc-state/1`, значения параметров, нормализация, история |
| `music.js` | `disc-music/1`, три явных источника, события и native Patterns |
| `three-view.js` | Геометрия диска, считывание, жесты |
| `controls.js` | Компактная панель и состояние меню |
| `app.js` | Транспорт, загрузка, сохранения и соединение компонентов |

Используются существующие Three.js 0.160.1, Strudel 1.3.0, композиционный
загрузчик, банк, `PhaseCubeTransport`, `PuzzleStage` и `PuzzlePointer`.
Новый аудиодвижок или парсер нот не вводится. `music-puzzle/3` не изменён:
у свободного эксперимента нет эталона, победы, перемешивания или решателя.

Музыкальные изменения применяются общим транспортом после его lookahead.
Геометрия звучащих событий читает **активную** музыкальную ревизию, не ещё
ожидающую изменения. Во время жеста указатель настройки показывает намерение.
Звук и считываемый рисунок переходят в новое состояние вместе.

## Проверки

`node --test disc/test-model.cjs` — точность исходных событий, полный оборот,
независимость партий, тишина, отмена, сохранение, длительности через шов.

`node disc/test-browser.mjs` — реальные цели Three-raycast, мышь/тач,
громкость/фаза/подключение/вариант, аудиотранспорт и геометрия, сохранение.
`node disc/test-recovery.mjs` — реальная потеря WebGL-контекста во время
перетаскивания: отмена жеста, сохранность настроек, восстановление ввода и звука.

Отчёты и снимки находятся в `disc/qa/`. Автоматические проверки не заменяют
авторский плейтест понятности или проверку физического iPhone.
